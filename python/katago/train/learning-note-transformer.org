#+TITLE: Transformer 架構 KataGo 訓練程式碼分析

* 概述 (Overview)
此目錄包含使用 Transformer 架構而非標準 ResNet/CNN 方法來訓練 KataGo 模型的實
驗性/非官方實作。它將現代 LLM 技術（RoPE, SwiGLU, RMSNorm）整合到 KataGo 的策
略/價值網路框架中。
* 模型配置 (Model Configs)

~train_transformer_katago/modelconfigs.py~ 定義了幾個 Transformer 特定的配置（例
如 ~b14c192h6tfrs~).

- ~tfrs~ 後綴可能代表 Transformer + RoPE + SwiGLU。
- 配置指定了 ~transformer_heads~, ~transformer_ffn_channels~ 等。

* 模型架構分析 (Model Architecture Analysis)
基於 ~train_transformer_katago/model_pytorch.py~ 中的 ~class Model~ 分析，這是一
個針對圍棋設計的多輸入、多輸出 ResNet/Transformer 混合架構。
** 1. 輸入層 (Inputs)
模型接受三個主要輸入：
- ~input_spatial~ (Batch, InputChannels, Height, Width): 代表棋盤狀態的空間特徵。
- ~input_global~ (Batch, GlobalFeatures): 代表全局遊戲狀態資訊。
- ~input_meta~ (Optional): 可選的元數據張量。

** 2. 主幹網路 (Trunk / Body)
負責將輸入處理為通用表示，然後分流到各個 Head。
- 嵌入與融合:
  - ~conv_spatial~: 根據配置 (~initial_conv_1x1~) 使用 1x1 或 3x3 卷積處理空間輸入
    (位於 ~Model.__init__~)。即使是 Transformer 架構，第一層仍然是 CNN (Conv2d)
    以將輸入特徵投影到嵌入空間。
  - ~linear_global~: 線性投影全局輸入。
  - 兩者相加融合 (~out = x_spatial + x_global~)。
- 區塊堆疊 (Blocks):
  - 由配置中的 ~block_kind~ 定義一系列區塊。
  - 支援標準 ~ResBlock~, 瓶頸層 ~BottleneckResBlock~。
  - 廣泛支援多種 Transformer 變體 (在 `Model` 類別中初始化)：
    - ~transformer~: 標準 Transformer Block。
    - ~transformerg~: 支援 RoPE 和 GQA 的 Transformer Block。
    - ~transformersg~: 支援 RoPE, GQA 和 SwiGLU 的 Transformer Block。
    - 以及其他變體 (~transformerropeg~, ~transformerropesg~) 用於細粒度控制 RoPE 的使用。
  - 這些 Transformer 區塊整合了 RoPE (旋轉位置編碼)、GQA (分組查詢注意力) 和
    SwiGLU 等技術。

** 3. 中間 Head (Intermediate Head) - 可選
如果配置啟用 (~has_intermediate_head~)，在主幹網路的中段會分出一條支路。
- 經過標準化 (~norm_intermediate_trunkfinal~) 後，連接到獨立的策略 (~Intermediate
  Policy Head~) 和價值 (~Intermediate Value Head~) 輸出。
- 這有助於深層網路的梯度傳遞和訓練穩定性。

** 4. 輸出 Head (Output Heads)
主幹輸出經標準化 (~norm_trunkfinal~) 後進入兩個主要分支：

*** A. 策略 Head (Policy Head)
- 輸入形狀: ~(B, c_trunk, H, W)~
- 雙路徑結構:
  1. ~conv1p~: 1x1 卷積路徑。
  2. ~conv1g~ -> Global Pooling (~KataGPool~) -> Linear: 全局資訊路徑。
- 融合: 將空間路徑與全局路徑相加。
- 輸出:
  - 棋盤移動 Logits (經 ~conv2p~)。這不是將所有通道壓縮成一個數字，而是將 $C$ 個
    通道壓縮成少數幾個通道 (通常是 4 或 6)，保持 $H \times W$ 的空間維度，每個位置
    都有對應的數值。
  - Pass (停著) Logits (經獨立線性層)。

*** B. 價值 Head (Value Head)
- 輸入形狀: ~(B, c_trunk, H, W)~
- 處理:
  - ~conv1~ -> Global Pooling (~KataValueHeadGPool~) -> Linear (~linear2~)。
  - 這裡確實發生了「通道塌縮」成單一數值的過程。~KataValueHeadGPool~ 計算整個棋盤特徵的平均值 (Mean) 和加權平均，將空間維度 ($H \times W$) 移除，只留下全局特徵向量，最後透過 Linear 層輸出單一數值 (如勝率)。
- **多重輸出**:
  - ~out_value~: 勝/負/無結果 (Win/Loss/NoResult)。
  - ~out_miscvalue~: 分數均值、標準差、領先目數等。
  - ~out_scorebelief_logprobs~: 預期分數差異的詳細分佈。
  - 輔助空間輸出: 領地歸屬 (~ownership~)、目數預測 (~scoring~) 等。
* 優化器：Muon 
訓練迴圈使用一個名為 Muon 的自定義優化器
(~train_transformer_katago/muon_kissin.py~)，改編自 "Moonlight" 專案。
- 機制：Muon 是一種動量 SGD 優化器，但它不直接更新權重，而是將權重矩陣投影到正交群上。
  這相當於對梯度進行白化 (whitening) 處理，使得每一步更新都能更有效地調整權重的內部結構。
  - 為什麼投影到正交群？
    這確保了更新矩陣 $U$ 滿足 $U^T U = I$。這樣的更新具有「最大化梯度相關性」
    的特性，同時約束了更新步長在各個方向上的尺度。簡單來說，標準 SGD 可能會因
    為某些特徵值的尺度過大而導致訓練不穩定；透過投影到正交群，Muon 強制讓所有
    奇異值都為 1，這意味著它在所有方向上以相同的「速度」學習，防止梯度爆炸或消
    失，並允許使用比傳統優化器大得多的學習率。
- 具體運作：它使用 Newton-Schulz 迭代法來高效計算矩陣的逆平方根，從而實現近似
  正交化，而無需昂貴的 SVD 分解。迭代公式：$X_{k+1} = \frac{1}{2} X_k (3I - X_k^T
  X_k)$ (此為 NS 迭代的一種形式，Muon 使用更高級的五階變體)。
- 它根據參數的形狀（2D 與更大）和名稱（例如跳過嵌入/輸出層）以不同方式處理參數。
- 它與輔助的 Adam 優化器結合使用 (~MuonWithAuxAdamKimi~)，通常 Muon 負責主要的
  Transformer 矩陣（如 Attention 和 FFN），而 Adam 負責 Embedding 和
  Normalization 層。

* Transformer Block 詳解 (Transformer Block Details)
本節深入分析 ~train_transformer_katago/model_pytorch.py~ 中定義的 Transformer 區
塊，特別是 ~TransformerRoPEGQABlock~ 。
** 1. 結構與層數 (Structure & Layers)
在程式碼中，一個 ~TransformerRoPEGQABlock~ 類別實例代表 Transformer 架構中的一層 (One Layer)。
每個 Block 包含兩個主要的子層 (Sub-layers)：
1. Attention Sub-layer: 包含 RMSNorm, Q/K/V 投影, RoPE 旋轉, Attention 計算
   (SDPA), 以及輸出投影。
2. Feed-Forward Sub-layer (FFN): 包含 RMSNorm, SwiGLU (或是標準 Activation),
   以及線性層。

雖然類別名為 "Block"，但從架構深度來看，它對應的是 Transformer 的一層。模型的
總深度由配置檔 (~modelconfigs.py~) 中的 ~block_kind~ 列表長度決定。如果列表中有 6
個 ~'transformersg'~, 模型就會堆疊 6 層這樣的 Block。

** 2. 關鍵組件與維度 (Components & Sizes)
假設配置中的主幹通道數為 ~c_main~ (例如 256)，頭數為 ~num_heads~ (例如 8)。

- Q/K/V 投影 (Projections):
  程式碼明確定義了三個線性層來生成 Query, Key, Value：
  #+BEGIN_SRC python
  self.q_proj = torch.nn.Linear(c_main, c_main, bias=False)
  self.k_proj = torch.nn.Linear(c_main, self.num_kv_heads * self.head_dim, bias=False)
  self.v_proj = torch.nn.Linear(c_main, self.num_kv_heads * self.head_dim, bias=False)
  #+END_SRC
  - ~q_proj~: 輸出維度保持 ~c_main~ 。
  - ~k_proj~ / ~v_proj~: 為了支援 GQA (Grouped Query Attention)，輸出維度較小。如果是標準 MHA，則與 Q 相同。
  - ~head_dim~ (每個頭的維度) = ~c_main // num_heads~ (例如 256/8 = 32)。

- RoPE (旋轉位置編碼):
  - 應用於 Query 和 Key。
  - 程式碼： ~q, k = apply_rotary_emb(q, k, self.cos_cached, self.sin_cached)~
  - 這是將棋盤的 2D 空間資訊注入到 Transformer 的關鍵步驟，否則 Attention 機制無法區分棋盤上的位置。

- FFN (前饋網路):
  - 維度 (~ffn_dim~) 通常定義為 ~c_main * 2~ (在 ~modelconfigs.py~ 中可配置)。
  - 結構 (若啟用 SwiGLU):
    $FFN(x) = (SiLU(xW_1) \otimes xW_{gate})W_2$
    程式碼對應：
    #+BEGIN_SRC python
    x1 = self.ffn_linear1(xn)      # W1
    x_gate = self.ffn_linear_gate(xn) # W_gate
    x1 = self.ffn_act(x1) * x_gate # SiLU(W1) * W_gate
    x1 = self.ffn_linear2(x1)      # W2
    #+END_SRC

** 3. 運作流程 (Workflow)
輸入 x 形狀為 (B, C, H, W) = (Batch, Channel, Height, Width)。
1. Reshape: 轉換為序列格式 (B, S, C)，其中 S = H \times W。
2. Pre-Norm: 使用 ~RMSNorm~ 進行歸一化。
3. Q/K/V 生成: 通過上述線性層。
4. RoPE: 對 Q, K 進行旋轉。
5. GQA Expand: 如果使用 GQA，將 K, V 擴展以匹配 Q 的頭數 (為了相容 PyTorch 的 ~scaled_dot_product_attention~)。
6. Attention: 計算 $\text{Softmax}(\frac{QK^T}{\sqrt{d}})V$。
7. Residual 1: $x = x + \text{AttentionOutput}$。
8. Pre-Norm: 再次 ~RMSNorm~ 。
9. FFN: 通過 SwiGLU 網路。
10. Residual 2: $x = x + \text{FFNOutput}$。
11. Reshape Back: 轉回 (B, C, H, W) 以供後續層或 CNN 輸出頭使用。

* 匯出與推論 (Export & Inference)
- ONNX 匯出：提供了 ~export_onnx.py~ 用於將訓練好的 PyTorch 檢查點轉換為
  ONNX。這包括量化支援 (INT8) 和元數據注入。
  - ONNX 的優勢：
    1. 跨平台相容性：ONNX (Open Neural Network Exchange) 是一個開放標準，允許模型脫離 PyTorch 環境，在不同的推論引擎（如 ONNX Runtime, TensorRT）上運行。
    2. 硬體加速：支援透過 TensorRT 等工具針對特定硬體（NVIDIA GPU）進行圖層融合 (Layer Fusion) 和核心優化，通常能比原生 PyTorch 執行得更快。
    3. 部署靈活性：KataGo 的 C++ 引擎整合 ONNX Runtime 後，可以直接讀取這種標
       準格式，而不需要手寫複雜的 C++ 權重載入邏輯來對應 Transformer 的複雜結
       構。
- 傳統匯出： ~export_model_pytorch.py~ 用於匯出為標準 KataGo `.bin` 格式，
  但 README 建議 Transformer 模型主要用於透過修改後的 KataGo 引擎 ("KataGomo")
  使用 ONNX。

* 原始 KataGo 與 Transformer 版架構差異詳解
此章節詳細比較原始實作 (~model_pytorch.py~) 與 Transformer 變體
(~train_transformer_katago/model_pytorch.py~) 的關鍵差異，並整合了新引入技術的
背景知識。

** 1. 核心區塊：ResNet vs Transformer (Core Blocks)
- **原始版**: 純粹的 ResNet 架構。
  - 依賴 ~ResBlock~, ~BottleneckResBlock~ (以及巢狀變體) 進行特徵提取。
  - 所有運算皆基於卷積神經網路 (CNN)，具有平移不變性和局部性，但缺乏全局 Attention 能力。

- **Transformer 版**: 混合架構。
  - 除了保留 ResNet 區塊外，新增了 ~TransformerBlock~ 與 ~TransformerRoPEGQABlock~。
  - 核心變更與術語解釋：
    - **Self-Attention**: 引入了全域注意力機制處理棋盤特徵。
    - **RoPE (Rotary Positional Embeddings, 旋轉位置編碼)**:
      - /程式碼/: ~precompute_freqs_cos_sin_2d~
      - /原理/: 通過將 Query 和 Key 向量在複平面上旋轉來編碼相對位置。對於圍棋這種 2D 網格，它將 x 和 y 軸的頻率分開計算，使得模型能感知棋子間的相對距離和方向。
      - /優勢/: 相比絕對位置編碼，RoPE 對於棋盤大小的泛化能力更好，且保留了平移不變性。
    - **GQA (Grouped Query Attention, 分組查詢注意力)**:
      - /機制/: 將 Query Heads 分組，每組共用一個 Key/Value Head。
      - /優勢/: 介於 MHA (多頭注意力) 和 MQA (多查詢注意力) 之間，大幅減少 KV Cache (或參數/頻寬需求)，同時保持比 MQA 更好的表現。
    - **SwiGLU**:
      - /程式碼/: FFN 中使用 ~Swish(xW) * (xV)~ 結構。
      - /差異/: 取代了標準 Transformer 中兩個線性層夾一個 ReLU/GELU 的結構。
      - /來源/: 現代 LLM (如 LLaMA) 常見改進，能提供更好的收斂性。

** 2. 正規化層 (Normalization)
- **原始版**: 
  - 主要使用 ~NormMask~ 類別封裝 Batch Normalization (~bnorm~) 或各種 Fixup 初始化變體。

- **Transformer 版**:
  - **RMSNorm (Root Mean Square Normalization)**:
    - 在 Transformer 區塊中取代 LayerNorm。
    - /原理/: 省略了 LayerNorm 的均值中心化步驟，僅根據均方根進行縮放。
    - /優勢/: 計算更高效，且對深層網路訓練更穩定（減少梯度爆炸/消失風險）。
  - **QAT 支援**: 保留了 ~NormMask~ 用於 CNN 部分，但增加了針對 INT8 量化訓練 (QAT) 的支援 (~MAYBE_QAT~ 標記)。

** 3. 激活函數 (Activation Functions)
- **原始版**: 支援 ReLU, ELU, Mish, GELU, Hardswish。
- **Transformer 版**: 
  - 新增支援 **SiLU** (Sigmoid Linear Unit, 即 Swish)。
  - 這是 SwiGLU 架構的核心組成部分 (SwiGLU = SiLU-gated linear unit)。

** 4. 量化與優化支援 (Quantization & Optimization)
- 原始版: 較少顯式的量化代碼。
- Transformer 版:
  - QAT 支援: 程式碼中包含大量 ~QuantStub~ 與 ~MAYBE_QAT~ 邏輯，明確針對 TensorRT 的 INT8 推論進行優化。
  - Torch Dynamo: 引入 ~torch._dynamo~ 進行編譯優化。
  - PyTorch 版本檢查: 強制要求較新的 PyTorch 版本 (2.7+ ? 程式碼中註解提及)，以避開舊版 NaN 問題。

** 5. 輸出頭 (Output Heads)
- 原始版: 策略頭 (~PolicyHead~) 與價值頭 (~ValueHead~) 的邏輯相對標準。
- Transformer 版:
  - ~PolicyHead~ 的輸出處理中，對於 Mask 外部區域的處理邏輯增加了常數張量優化 (~self.t_1~, ~self.t_5000~)，以利於 TensorRT INT8 轉換。
  - 雖然結構相似，但 Transformer 版在許多運算細節上（如常數宣告為 buffer）都為了硬體部署做了微調。

* 檔案摘要 (File Synopses)
本節列出專案中各檔案的功能摘要。
- ~train_transformer_katago/dummy_input.py~: 用於生成隨機的虛擬輸入數據，供測試
  模型結構或初始化使用，無需真實數據。
- ~train_transformer_katago/muon_kissin.py~: 實作了 Muon 優化器。這是一個動量
  SGD 的變體，利用牛頓-舒爾茨迭代 (Newton-Schulz iteration) 進行權重的近似正交
  化，並結合輔助的 Adam 優化器，專為大規模訓練設計。
- ~train_transformer_katago/view_loss.py~: 工具腳本，用於讀取訓練過程中產生的
  JSON 指標檔案，並繪製損失 (Loss) 隨時間變化的曲線圖。
- ~train_transformer_katago/shuffle.sh~: Shell 腳本，用於定期呼叫 ~shuffle.py~ 來
  打亂和整理 self-play 產生的數據，準備供訓練使用的數據塊。
- ~train_transformer_katago/clean_checkpoint.py~: 用於清理 PyTorch 檢查點檔案，
  移除優化器狀態、歷史訓練數據路徑等元數據，以減小發布模型時的檔案大小。
- ~train_transformer_katago/export.sh~: 自動化匯出訓練模型的腳本，監控訓練目錄，
  將 PyTorch 檢查點轉換為可供 KataGo 引擎使用的格式並移動到指定目錄。
- ~train_transformer_katago/metrics_pytorch.py~: 定義了訓練和評估過程中的各種損
  失函數 (Loss Functions)（如策略損失、價值損失、死活題損失等）以及評估指標的
  計算邏輯。
- ~train_transformer_katago/make_superswa.py~: 透過對多個歷史檢查點進行平均
  (SWA) 或取中位數等操作，創建一個更穩定、泛化能力更好的 "Super SWA" 模型檢查
  點。
- ~train_transformer_katago/export_onnx.py~: 將訓練好的 PyTorch 模型匯出為 ONNX
  格式。支援 INT8 量化 (QAT)、模型簡化，以及添加元數據，以便在 TensorRT 等高效
  能推理引擎上運行。
- ~train_transformer_katago/replace_using_swa.py~: 一個工具腳本，用於將檢查點中
  的原始模型權重替換為 SWA (隨機權重平均) 模型的權重。
- ~train_transformer_katago/modelconfigs.py~: 定義了各種模型架構的配置參數字典
  （如層數、通道數、Transformer 頭數、激活函數類型等），供模型初始化使用。
- ~train_transformer_katago/summarize_old_selfplay_files.py~: 用於掃描和匯總舊的
  self-play 數據文件 (.npz) 的元數據（如行數、時間戳），用於數據管理。
- ~train_transformer_katago/README.md~: 專案的主要說明文件，介紹如何訓練

** Model Configuration Details

*** Terminology
- **Layers**: The number of Transformer blocks stacked in the model. In this architecture, "Layer" and "Block" are used interchangeably; e.g., a model with 18 layers consists of 18 sequential Transformer blocks.
- **Trunk Channels**: The size of the hidden vector representation (embedding dimension) for each position on the board. Often denoted as $d_{model}$.
- **Transformer Heads**: The number of attention heads used for the Query ($Q$) in the Self-Attention mechanism. For each of the $19 \times 19 = 361$ points on the board, the model generates **Transformer Heads** distinct Query vectors.
- **KV Heads**: The number of attention heads used for Keys ($K$) and Values ($V$). If this is smaller than **Transformer Heads**, the model uses Grouped Query Attention (GQA).
  - *Explanation*: Instead of having a unique K and V vector for every Q head (standard Multi-Head Attention), multiple Q heads share the same K and V heads.
  - *Example*: If Transformer Heads = 12 and KV Heads = 4, then every 3 Q heads share 1 K head and 1 V head. This significantly reduces the memory bandwidth required to load K/V pairs during inference and training.
- **FFN Channels**: The hidden dimension size of the Feed-Forward Network (FFN) sub-layer within each Transformer block. In SwiGLU configurations, this is the size of the intermediate projection before the gating mechanism.
