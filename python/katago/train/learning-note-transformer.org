#+TITLE: Transformer 架構 KataGo 訓練程式碼分析

* 概述 (Overview)
此目錄包含使用 Transformer 架構而非標準 ResNet/CNN 方法來訓練 KataGo 模型的實
驗性/非官方實作。它將現代 LLM 技術（RoPE, SwiGLU, RMSNorm）整合到 KataGo 的策
略/價值網路框架中。
* 關鍵架構變更 (Key Architectural Changes)
** Transformer 區塊 (Transformer Blocks)
核心邏輯位於 ~train_transformer_katago/model_pytorch.py~。
它實作了 ~TransformerRoPEGQABlock~ 來取代標準的殘差區塊 (Residual Blocks)。
*** RoPE (旋轉位置編碼)
使用 2D RoPE (~precompute_freqs_cos_sin_2d~) 來處理圍棋棋盤的空間網格。
- 原理：RoPE 通過將查詢 (Query) 和鍵 (Key) 向量旋轉一個角度來編碼相對位置訊息。
  具體來說，它將嵌入向量中的特徵成對分組，並視為複平面上的點。對於位置 $m$ 和頻率 $\theta$，
  它透過乘以 $e^{i m \theta}$ 進行旋轉：
  
  $f_{q,k}(x_m, m) = (x_m + i y_m) e^{i m \theta} = (x_m \cos(m\theta) - y_m \sin(m\theta)) + i(x_m \sin(m\theta) + y_m \cos(m\theta))$

  對於圍棋這種 2D 網格，它將 x 和 y 軸的頻率分開計算，將一半的特徵用於編碼 X
  坐標，另一半用於編碼 Y 坐標，使得模型能夠感知棋子之間的相對歐幾里得距離和方
  向。
- 優勢：相比於絕對位置編碼 (Absolute PE)，RoPE 對於序列長度（棋盤大小）的泛化
  能力更好，且能保留平移不變性 (translation invariance) 的特性，這對於理解局部
  棋形非常重要。

*** SwiGLU
在前饋神經網路 (FFN) 中使用 SwiGLU 激活函數。
- 公式：SwiGLU(x) = Swish(xW) \cdot (xV)，其中 Swish(z) = z \cdot sigmoid(z)。
- 結構：標準 Transformer 的 FFN 通常是兩個線性層中間夾一個 ReLU/GELU。SwiGLU
  則使用了三個線性映射（Gate, Value, Output），雖然增加了參數量，但在相同的計
  算預算下通常能提供更好的收斂性和性能。
- 來源：這是現代 LLM（如 LLaMA, PaLM）中常見的架構改進。

*** RMSNorm
取代 LayerNorm (Layer Normalization)。
- 差異：RMSNorm (Root Mean Square Normalization) 省略了 LayerNorm 中的均值中心
  化 (mean centering) 步驟，僅根據均方根進行縮放。
- 公式：
  $\bar{a}_i = \frac{a_i}{\text{RMS}(a)} g_i, \quad \text{where } \text{RMS}(a)
             = \sqrt{\frac{1}{n} \sum_{i=1}^{n} a_i^2}$
  其中 $g_i$ 是可學習的縮放參數。
- 優勢：計算上更簡潔高效，且在實驗中發現對於深層 Transformer 的訓練穩定性有幫
  助。它讓梯度在反向傳播時更穩定，減少了梯度消失或爆炸的風險。

*** GQA (分組查詢注意力)
程式碼支援 GQA (Grouped Query Attention)。
- 機制：介於 MHA (Multi-Head Attention) 和 MQA (Multi-Query Attention) 之間。
  MHA 每個 Query Head 都有對應的 Key/Value Head；MQA 所有 Query Head 共用一組
  Key/Value Head。GQA 則是將 Query Heads 分組，每組共用一個 Key/Value Head。
- 目的：大幅減少 KV Cache 的大小（雖然在圍棋這種固定長度的場景下，主要優勢是減
  少參數和推理時的記憶體頻寬需求），同時保持比 MQA 更好的模型表現。
- 現狀：README 指出它在此實作中可能被禁用或是實驗性的，視具體配置而定。

* 模型架構分析 (Model Architecture Analysis)
基於 ~train_transformer_katago/model_pytorch.py~ 中的 ~class Model~ 分析，這是一
個針對圍棋設計的多輸入、多輸出 ResNet/Transformer 混合架構。
** 1. 輸入層 (Inputs)
模型接受三個主要輸入：
- ~input_spatial~ (Batch, InputChannels, Height, Width): 代表棋盤狀態的空間特徵。
- ~input_global~ (Batch, GlobalFeatures): 代表全局遊戲狀態資訊。
- ~input_meta~ (Optional): 可選的元數據張量。

** 2. 主幹網路 (Trunk / Body)
負責將輸入處理為通用表示，然後分流到各個 Head。
- 嵌入與融合:
  - ~conv_spatial~: 使用 1x1 或 3x3 卷積處理空間輸入。
  - ~linear_global~: 線性投影全局輸入。
  - 兩者相加融合 (~out = x_spatial + x_global~)。
- 區塊堆疊 (Blocks):
  - 由配置中的 ~block_kind~ 定義一系列區塊。
  - 支援標準 ~ResBlock~, 瓶頸層 ~BottleneckResBlock~, 以及各種 Transformer 變體 (~TransformerRoPEGQABlock~ 等)。
  - 這些 Transformer 區塊整合了 RoPE (旋轉位置編碼)、GQA (分組查詢注意力) 和 SwiGLU 等技術。

** 3. 中間 Head (Intermediate Head) - 可選
如果配置啟用 (~has_intermediate_head~)，在主幹網路的中段會分出一條支路。
- 經過標準化 (~norm_intermediate_trunkfinal~) 後，連接到獨立的策略 (~Intermediate Policy Head~) 和價值 (~Intermediate Value Head~) 輸出。
- 這有助於深層網路的梯度傳遞和訓練穩定性。

** 4. 輸出 Head (Output Heads)
主幹輸出經標準化 (~norm_trunkfinal~) 後進入兩個主要分支：

*** A. 策略 Head (Policy Head)
- 輸入形狀: ~(B, c_trunk, H, W)~
- **雙路徑結構**:
  1. ~conv1p~: 1x1 卷積路徑。
  2. ~conv1g~ -> Global Pooling (~KataGPool~) -> Linear: 全局資訊路徑。
- **融合**: 將空間路徑與全局路徑相加。
- **輸出**:
  - 棋盤移動 Logits (經 ~conv2p~)。
  - Pass (停著) Logits (經獨立線性層)。

*** B. 價值 Head (Value Head)
- 輸入形狀: ~(B, c_trunk, H, W)~
- **處理**:
  - ~conv1~ -> Global Pooling (~KataValueHeadGPool~) -> Linear (~linear2~)。
- **多重輸出**:
  - ~out_value~: 勝/負/無結果 (Win/Loss/NoResult)。
  - ~out_miscvalue~: 分數均值、標準差、領先目數等。
  - ~out_scorebelief_logprobs~: 預期分數差異的詳細分佈。
  - 輔助空間輸出: 領地歸屬 (~ownership~)、目數預測 (~scoring~) 等。
* 優化器：Muon (Optimization: Muon)
訓練迴圈使用一個名為 Muon 的自定義優化器
(~train_transformer_katago/muon_kissin.py~)，改編自 "Moonlight" 專案。
- 機制：Muon 是一種動量 SGD 優化器，但它不直接更新權重，而是將權重矩陣投影到正交群上。
  這相當於對梯度進行白化 (whitening) 處理，使得每一步更新都能更有效地調整權重的內部結構。
  - 為什麼投影到正交群？
    這確保了更新矩陣 $U$ 滿足 $U^T U = I$。這樣的更新具有「最大化梯度相關性」
    的特性，同時約束了更新步長在各個方向上的尺度。簡單來說，標準 SGD 可能會因
    為某些特徵值的尺度過大而導致訓練不穩定；透過投影到正交群，Muon 強制讓所有
    奇異值都為 1，這意味著它在所有方向上以相同的「速度」學習，防止梯度爆炸或消
    失，並允許使用比傳統優化器大得多的學習率。
- 具體運作：它使用 Newton-Schulz 迭代法來高效計算矩陣的逆平方根，從而實現近似
  正交化，而無需昂貴的 SVD 分解。迭代公式：$X_{k+1} = \frac{1}{2} X_k (3I - X_k^T
  X_k)$ (此為 NS 迭代的一種形式，Muon 使用更高級的五階變體)。
- 它根據參數的形狀（2D 與更大）和名稱（例如跳過嵌入/輸出層）以不同方式處理參數。
- 它與輔助的 Adam 優化器結合使用 (~MuonWithAuxAdamKimi~)，通常 Muon 負責主要的
  Transformer 矩陣（如 Attention 和 FFN），而 Adam 負責 Embedding 和
  Normalization 層。

* 訓練流程 (Training Pipeline) - (~train_muon_ki.py~)
- 多 GPU (Multi-GPU)：支援 DistributedDataParallel (DDP)。
- FP16/AMP：支援混合精度訓練。
- SWA (隨機權重平均)：大量用於提高泛化能力。
- 資料載入 (Data Loading)：讀取打亂後的 ~.npz~ 檔案（標準 KataGo 格式）。
- Lookahead Optimizer：可選支援 Lookahead 包裝器。

* 匯出與推論 (Export & Inference)
- ONNX 匯出：提供了 ~export_onnx.py~ 用於將訓練好的 PyTorch 檢查點轉換為
  ONNX。這包括量化支援 (INT8) 和元數據注入。
  - ONNX 的優勢：
    1. 跨平台相容性：ONNX (Open Neural Network Exchange) 是一個開放標準，允許模型脫離 PyTorch 環境，在不同的推論引擎（如 ONNX Runtime, TensorRT）上運行。
    2. 硬體加速：支援透過 TensorRT 等工具針對特定硬體（NVIDIA GPU）進行圖層融合 (Layer Fusion) 和核心優化，通常能比原生 PyTorch 執行得更快。
    3. 部署靈活性：KataGo 的 C++ 引擎整合 ONNX Runtime 後，可以直接讀取這種標
       準格式，而不需要手寫複雜的 C++ 權重載入邏輯來對應 Transformer 的複雜結
       構。
- 傳統匯出： ~export_model_pytorch.py~ 用於匯出為標準 KataGo `.bin` 格式，
  但 README 建議 Transformer 模型主要用於透過修改後的 KataGo 引擎 ("KataGomo")
  使用 ONNX。

* 有趣的觀察 (Interesting Observations)
- 歷史矩陣 (History Matrices)： ~data_processing_pytorch.py~ 中有特定的 "歷史矩
  陣" 邏輯，似乎用於處理與先前步數或棋盤狀態相關的輸入特徵，這是圍棋特有的。
- 對稱性 (Symmetry)：程式碼在訓練資料增強期間處理圍棋的 8 倍對稱性（旋轉/
  反射）。
- QAT (量化感知訓練)：有輔助程式 (~qat_helper.py~) 用於 TensorRT 相容的 INT8
  量化，顯示其專注於高效能推論。
